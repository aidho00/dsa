04 Main Idea

Today's Big Question

If a tree has many nodes, how do we make Java visit them all?

Answer: we follow a traversal order.

05 Simple Definition

What Is Traversal?

Traversal means visiting every node in a data structure.

Real Life

Checking every room in a building

In Trees

Checking every node using a clear order

Traversal is a systematic way to visit every reachable node exactly in a chosen order.

06 Purpose

Why Do We Traverse Trees?

  • To display all values stored in the tree
  • To search, count, or process nodes
  • To copy or delete the tree properly
  • To convert tree data into a list-like order
  • To understand how tree algorithms move

Trees have no single next position, so traversal rules determine which branch is processed first.

07 Traversal Types

The Three Main Orders

Inorder

Left → Root → Right

Preorder

Root → Left → Right

Postorder

Left → Right → Root

Same tree, different visiting order.

The order names describe when the root is processed relative to the left and right subtrees.

09 Memory Aid

Think of It Like Instructions

Inorder: Go left first, print the current node, then go right.

Preorder: Print first, then go left, then go right.

Postorder: Go left, go right, then print last.

10 Needed Idea

Important Word: Recursion

Traversal is usually written using recursion.

A recursive method is a method that calls itself to solve a smaller part of the same problem.

Do not worry. Today, we will trace it slowly.

Each recursive call solves the same traversal problem for one smaller subtree.

11 Base Case

The Stop Rule

if (node == null) {
    return;
}

This means: if there is no node, stop and go back.

When the current node is null, that branch is empty and the method returns without accessing fields.

12 Code Pattern

Traversal Method Shape

static void traversal(TreeNode node) {
    if (node == null) {
        return;
    }

    // visit left side
    // print current node
    // visit right side
}

Only the order of these three actions changes.

Every traversal combines a root action with recursive visits to the left and right children.

13 Traversal 1

Start with Inorder

Left → Root → Right

For beginners, this is the most important traversal to understand first.

Inorder processes the entire left subtree, then the root, then the entire right subtree.

14 Slow Explanation

Inorder in Plain English

  • Go to the left child first
  • When there is no more left child, print the current node
  • Then go to the right child
  • Repeat the same rule for every small subtree
15 Before Java

Inorder Pseudocode

inorder(node)
    if node is null
        stop
    inorder(node.left)
    print node.data
    inorder(node.right)

This is not Java yet. This is the idea before coding.

16 Core Code

Inorder Java Code

static void inorder(TreeNode node) {
    if (node == null) {
        return;
    }

    inorder(node.left);
    System.out.println(node.data);
    inorder(node.right);
}

The print statement belongs between the two recursive calls because the root is visited second.

19 Key Connection

Why Inorder Gives Sorted Values

In a Binary Search Tree:

  • Smaller values are on the left side
  • Larger values are on the right side
  • Inorder reads left first, then root, then right
  • So it naturally reads from smallest to largest

Inorder produces sorted output only when the tree also satisfies the binary-search-tree ordering rule.

21 Traversal 2

Now Preorder

Root → Left → Right

Preorder prints the node before visiting its children.

Preorder handles the root before either subtree, which records the parent before its descendants.

22 Slow Explanation

Preorder in Plain English

  • Print the current node first
  • Then visit the left subtree
  • Then visit the right subtree
  • Useful when you want to process the parent before the children
23 Core Code

Preorder Java Code

static void preorder(TreeNode node) {
    if (node == null) {
        return;
    }

    System.out.println(node.data);
    preorder(node.left);
    preorder(node.right);
}
24 Expected Result

Preorder Output

10 5 3 7 15 12 18

The root appears first because preorder prints before going down.

25 Where It Helps

Preorder Use Case

Tree Copy

Create the root before creating its children.

File Systems

Show the folder before showing files inside it.

Preorder is useful for copying tree structure or producing prefix-style representations.

27 Traversal 3

Now Postorder

Left → Right → Root

Postorder prints the node after visiting its children.

Postorder processes both subtrees before the root, so children are handled before their parent.

28 Slow Explanation

Postorder in Plain English

  • Visit the left subtree first
  • Visit the right subtree next
  • Print the current node last
  • Useful when children must be processed before the parent
29 Core Code

Postorder Java Code

static void postorder(TreeNode node) {
    if (node == null) {
        return;
    }

    postorder(node.left);
    postorder(node.right);
    System.out.println(node.data);
}
30 Expected Result

Postorder Output

3 7 5 12 18 15 10

The root is printed last because postorder finishes children first.

31 Where It Helps

Postorder Use Case

Deleting a Tree

Delete children first before deleting the parent.

Expression Trees

Compute smaller parts before the final operation.

Postorder fits tasks such as deleting a tree or calculating results that depend on both children first.

33 Important Reminder

One Tree, Three Stories

Traversal does not change the tree.

It only changes the order in which we visit or print the nodes.

Same data. Different reading pattern.

36 Complete Methods

Traversal Methods Together

class TreeNode {
    int data;
    TreeNode left;
    TreeNode right;

    TreeNode(int data) {
        this.data = data;
    }
}

public class Main {
    static void inorder(TreeNode node) {
        if (node == null) {
            return;
        }
        inorder(node.left);
        System.out.print(node.data + " ");
        inorder(node.right);
    }

    static void preorder(TreeNode node) {
        if (node == null) {
            return;
        }
        System.out.print(node.data + " ");
        preorder(node.left);
        preorder(node.right);
    }

    static void postorder(TreeNode node) {
        if (node == null) {
            return;
        }
        postorder(node.left);
        postorder(node.right);
        System.out.print(node.data + " ");
    }
}

43 Debugging

Common Error: Forgetting null Check

// Dangerous: no stop rule
static void inorder(TreeNode node) {
    inorder(node.left);
    System.out.println(node.data);
    inorder(node.right);
}
Always check if node is null before reading node.left or node.right.

Without the null base case, recursion eventually tries to access fields through a missing child.

44 Debugging

Common Error: Wrong Order

// This is preorder, not inorder
System.out.println(node.data);
inorder(node.left);
inorder(node.right);

Small order changes create a different traversal.

Moving the root action changes the traversal type even when the recursive calls stay the same.

45 Recap

Summary

  • Traversal means visiting every node in a tree
  • Inorder is Left → Root → Right
  • Preorder is Root → Left → Right
  • Postorder is Left → Right → Root
  • Inorder traversal of a BST produces sorted values
